Race Lloyd against e-means

Oakley Comfort Co. is a made-up heating shop in Oakley, Cincinnati. The dots are made-up service calls on a made-up map of the east side. The shop wants a few route zones. Lloyd’s k-means reads every call, then parks each center on the average of the calls that chose it. The other map moves the centers from a small batch, using a fading sum and a fading count.

What k-means is doing

You pick k centers. Every call joins the nearest center. Then each center moves to the average of its calls. That pair of steps is Lloyd’s algorithm. The error is the average squared distance from a call to its center. It falls, then it sticks at a local minimum. It is not guaranteed to find the best grouping.

In a vector search library, this is often the slow offline step. FAISS and the same kind of index build a codebook by clustering the vectors before a search can run. The paper’s point is that this clustering, not the later lookup, is what takes the passes. The shop is a small picture of that grouping: tickets into route zones, not a billion embeddings.

What the fading average changes

e-means keeps, for each cluster, a sum S and a count N. The center is S / N. A batch of B calls is assigned to the nearest centers. If those calls contribute a sum s and a count n, the update is:

S ← (1 − α) S + α s, and N ← (1 − α) N + α n.

Old assignments fade. A running average, the 1967 MacQueen rule, never fades: it only adds s and n. Lloyd is the extreme where the batch is the whole set and α is 1, so S and N are replaced outright. The blog points out that this extreme sits in a bad corner of the settings they searched.

  1. The step and the batch are formulas. α and B come from n, k, and the pass budget. You do not grid-search them. This page uses the quality batch from the FAISS 1.16 readme, the one FAISS picks when the dimension is 16 or lower. The map is 2D.
  2. Cosine decay. α starts at α0 and cools to 0.1 α0 on a cosine curve, the same shape as a learning-rate schedule. The paper’s floor is 0.1.
  3. A light start. Centers begin as k random calls. N starts at 10−10, so that guess weighs almost nothing. The FAISS code uses 2−16 instead. This page follows the paper. The authors tried k-means++ and found it a bit better and much slower, so their default is this random start. Both maps here share it.
  4. Dead clusters. Every fifth batch, a cluster whose count is under 0.1 times the mean count is rebuilt by splitting a busy donor. The split nudges the donor by a factor of 0.0001, alternating by coordinate, and gives each child half the count. FAISS turns this off for dimension 2 and below, because the authors measured a held-out penalty on geographic sets. It stays on here so the switch does something.
  5. A short finish. The last pass records which calls joined which center, then each center becomes the plain average of those calls. The paper uses this as the default ending. On a million embeddings it moved the error by a fraction of a percent. On this map the change is small, and the page prints it.

Numbers the authors reported

These are their measurements, not a result from this page. The paper’s abstract is the source for the pass counts and the GPU range. The blog states the same result a bit more loosely, and adds the CPU range.

  • Passes. On their embedding sets, e-means gets under the loss Lloyd has after 25 epochs in 1.4 to 2.6 epochs. The blog phrases that span as 1.2 to 3 epochs.
  • Wall clock. They report about 10–45× less GPU time than Flash-KMeans at the same loss, and about 8–15× less CPU time than FAISS Lloyd. This page does not time either method. It counts passes and calls read.
  • Where it shipped. FAISS 1.16.0, 9 Nov 2026, as faiss.contrib.e_means. The library default is 5 passes. The readme says 5 is typically enough to beat Lloyd at convergence.

The scaling rule this page actually uses

FAISS writes the quality batch as B = 0.00439175 · k0.134749 · n0.876473 · T0.813344, rounded to the nearest power of two and capped near n / 2. The starting step is α0 = 0.8244 · k−0.4617 · B0.9003 · n−0.4498 · T−0.1057, clamped to the range 0.0001 to 1. The paper’s Table 2 prints those same laws more coarsely: batch coefficient 0.0044, step 0.824, −0.46, 0.90, −0.45, −0.11.

I did not refit the powers. The laws were fit on high-dimensional embeddings, from about 100,000 points up, and the paper says they are not optimal for very low dimension. This map is 2D and a few thousand calls, which is outside that fit. The quality batch is still the honest default: it is what FAISS selects on its own when the dimension is 16 or lower. On the default map, with every switch on, that rule puts the EMA run under Lloyd’s 25-pass error in fewer passes than the budget. A running average on the same calls does not get under that line. The check in this folder asserts both. The larger throughput batch, coefficient 0.035134, is FAISS’s choice above 16 dimensions. It is not used here.

Other seeds and other k are a different problem. This simplified copy will not win every one of them. Lloyd on this page is the textbook full-batch mean. It does not revive empty clusters. FAISS’s own Lloyd can.

The made-up map

Ten neighborhoods, placed by hand on a unit square. They are not geocodes. The blobs overlap, and they are different sizes, so a center can get stuck between them. The names are Oakley, Hyde Park, Madisonville, Norwood, Pleasant Ridge, Mount Lookout, Evanston, Kennedy Heights, O'Bryonville, and Columbia-Tusculum.

Try it for real

This is the CPU quick start from the contrib/e_means README, for FAISS 1.16. The update itself lives in base.py. Install with pip install faiss-cpu. On a GPU the class is Emeans, and you pass a tensor that is already on the device. The readme has that path.

import numpy as np
from faiss.contrib.e_means import NumpyEmeans

x = np.random.rand(200_000, 64).astype("float32")      # 200,000 vectors of dimension 64

em = NumpyEmeans(64, 500)                    # 500 clusters, 5 passes over the data by default
centroids, labels = em.train(x)          # (500, 64) float32, and each vector's cluster
x_new = np.random.rand(100_000, 64).astype("float32")
distances, new_labels = em.assign(x_new) # the nearest centroid of new vectors
