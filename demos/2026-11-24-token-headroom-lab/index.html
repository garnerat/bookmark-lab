Compress the tool output, keep the error

Juniper Hill Inn is a fictional 14-room inn. Its front-desk agent reads the booking system’s tool output before it answers. This page runs a toy compressor on three made-up samples and estimates tokens as characters ÷ 4.

Your agent reads a 10,000-token log file to find one error. You paid for all 10,000 tokens. The answer needed 1,200.

Headroom sits between your agent and the LLM and compresses everything before the model sees it.

JSON, code, logs, RAG chunks, each gets its own specialized compressor.

And it's reversible: the originals stay on your machine, so nothing is lost.

The post points at Headroom, the Apache-2.0 project. The pip and npm package name is headroom-ai. The same post also says “up to 95% fewer tokens” and “same accuracy on benchmarks.” Those are the post’s words. Headroom’s README claims 21–57% fewer input tokens on four agent scenarios, 90%+ on repeated JSON arrays and log lines, and little on prose.

Illustrative simulation. This is not Headroom’s actual code or benchmarks. Juniper Hill Inn does not exist. The reservations, the log, and the email were written for this page. Nothing here calls a network, a model, or an API. Token counts are a characters ÷ 4 estimate.

What Headroom’s README and docs describe

Headroom’s README says compression runs on your machine, on tool outputs, logs, JSON, RAG chunks, and chat history, before that text reaches the model. The picture in the README is CacheAligner, then a content router, then CCR. CacheAligner reports prefix drift and does not rewrite the prompt. The router picks the compressor.

  • JSON arrays. SmartCrusher. Headroom’s README says it keeps error items, values outside the normal range, and the first and last rows, chosen from field statistics rather than a keyword list.
  • Logs. The compression docs route build and test logs to a log compressor that keeps failures and stack traces and collapses repeated lines. Headroom’s README claims 90%+ fewer tokens on repeated JSON arrays and log lines.
  • Prose. Kompress. Headroom’s README claims little savings on prose, and short prose can come back unchanged.
  • CCR. Compress-Cache-Retrieve. The original stays in a local store. The compressed text carries a marker, and the model can call headroom_retrieve when it needs the full text.

Headroom’s README claims these measured input-token savings on four agent scenarios, with its own tokenizer: code search 21% (17,199 to 13,597), SRE debugging 57% (55,957 to 24,340), codebase exploration 42% (58,801 to 33,895), and GitHub issue triage 30% (46,067 to 32,429). This page does not rerun that table.

Docs: overview, architecture, how compression works, CCR.

Try it for real

    
Headroom’s README shows this library call for an app that already builds its messages. The model name is the README’s example. This page does not run it.

    
pip install headroom-ai

    
from headroom import compress

result = compress(messages, model="gpt-4o")

    
The post’s one-minute setup for a coding agent is pip install "headroom-ai[all]" and then headroom wrap claude.
