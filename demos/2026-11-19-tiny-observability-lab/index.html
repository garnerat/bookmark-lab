Tiny observability lab

Ironside Strength Co. is a made-up gym. Members book Dawn Iron, the 6:00 class, on a small web app. This page rebuilds one Thursday morning of that app: how many bookings, how slow they were, which ones failed, and the path a single booking took through the site, the API, Postgres, and the text provider.

Andrew bookmarked @Replit, 17 Nov 2026. The post links DataCat:

The leading observability platform wants $83,700/yr just to monitor your app and catch issues.

So Replit Missions built DataCat. 100% free.

DataCat is the free, self-hosted project in that repo: metrics, logs, traces, dashboards, and alerts, stored in PostgreSQL or ClickHouse, accepting OpenTelemetry. This page does not run DataCat. It simulates the three signals, on the gym’s booking app, so a slow class rush is visible without that contract.

Fictional gym, seeded numbers. Ironside Strength Co., the members, and Dawn Iron were written for this page. Member ids are made up. Nothing is a real person, and the page makes no network request. The same seed rebuilds the same morning.

What the stack is actually watching

Metrics

A number every 5 minutes: bookings, p50, average, p95, and the error rate. This is the chart.

Traces

One booking, as spans: the web page, booking-api, Postgres, then the confirmation text. A card charge would be the same kind of last hop.

Logs

The lines those services wrote. The trace_id on the line is the same id as the trace, so the slow query belongs to that member’s tap, not to the booking next to it.

Alert rule

A rule is a metric, a line, and a duration. It fires when the metric stays over the line for that long. Evaluation uses a strict greater-than, and the duration rounds up to 5-minute buckets.

    Try it yourself

    DataCat’s own README is the setup that was checked for this page. Do that, rather than a flag invented here.

    1. Clone github.com/replit/datacat and follow the Quick start in the README. It copies .env.example to .env, has you set POSTGRES_PASSWORD and SESSION_SECRET, then runs docker compose up -d --build. The UI is http://localhost:3000.
    2. OpenTelemetry SDKs send OTLP/HTTP to /v1/traces, /v1/metrics, and /v1/logs (also under /otlp/v1/*). Telemetry storage is PostgreSQL or ClickHouse, chosen with DATACAT_STORAGE. Both are in the self-hosting guide.
    3. The guide’s Node path, aimed at this booking app, is the documented variables with your service name:
    DATACAT_SERVICE=booking-api DATACAT_URL=https://observe.example.com \
  DATACAT_API_KEY="$YOUR_API_KEY" node -r @datacat/trace/init app.js

    DATACAT_URL is the origin without /otlp. The same guide covers a local agent on port 4318, and Python via datacat-run. Create the API key in the UI. Do not put a real key in a shell history you share.
