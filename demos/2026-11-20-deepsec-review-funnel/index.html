Security review funnel

Second Chance Paws Rescue is a made-up nonprofit. The app takes donations, volunteer sign-ups, and adoption applications. This page walks 22 short files from that app through the shape of a security review.

Andrew bookmarked a post by Dillon Mulroy recommending Vercel’s open-source deepsec. The repo is vercel-labs/deepsec. The Vercel page says:

deepsec is an open-source security review harness. It maps the security-sensitive surfaces in a repository, uses local matchers to select candidate files, sends coding agents through the relevant code paths, and revalidates their findings.

You start it with npx deepsec init at the repo root. This page does not add features, flags, or output formats beyond that description.

Simulation of the pipeline idea. This is not deepsec, and it does not scan a repository. The 22 files, the findings, and the token and time numbers were written for this page. The token and time numbers are made-up illustrative estimates. The agent traces are scripted. The switches change which of those scripted findings stay in the report. Nothing is uploaded. This page does not call a model or use the network. The key in the test fixture is not a real key.

The funnel

Per the project page, the harness does four things: map surfaces, select candidates with local matchers, send coding agents through those paths, and revalidate the findings. All files is the pile you start with. Tap a stage, then tap a file for the snippet and the trace.

Try it on your own repo

From the root of the repository you want reviewed:

npx deepsec init

A short list for a small org, using this rescue as the picture:

  1. Run it on a branch, not on the only copy of main. A noisy report is easier to drop that way.
  2. Read the revalidated findings first. Earlier stages still contain false positives. In this fictional repo those are the public pet page, the foster note, and the test-fixture key.
  3. Fix the auth and ownership bugs first. A route that loads an adoption application by id, with no check that the row belongs to the session, comes before anything cosmetic.
  4. Then the webhook that never checks a signature, the CSV export with no staff check, and the server-side fetch of a URL the caller supplied.
