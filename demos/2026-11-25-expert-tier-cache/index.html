Copperline Physical Therapy is a fictional outpatient clinic. Two clinicians and a front desk share an office Mac mini. It drafts visit notes and one-page home-exercise handouts, and the drafts stay in the building.

Andrew bookmarked Nick (@nickbaumann_), 24 Nov 2026, quoting Tom Greenwald (@tomgreenwald):

Magnitude splits the model into tiers:

1. GPU VRAM holds the shared model layers and most used experts

2. System RAM holds the next tier of frequently used experts

3. NVMe SSD holds the rest of the model and streams what's needed on demand

VRAM needs to fit at least the active experts. Beyond that, the more experts you can cache in VRAM / RAM, the faster it will be. And for whatever spills to disk, a faster SSD (like PCIe 5.0) makes a real difference.

What the posts and the docs say

Magnitude's README describes an open-source inference engine that spreads a model across the GPU, system RAM, and SSD so it runs on everyday Macs and PCs. The license is Apache-2.0. The README's account of a sparse mixture-of-experts model matches the quoted post: hundreds of experts, and only about 5% of them activate for each token.

  • Three tiers. The quoted post puts shared layers and the most-used experts in GPU VRAM, the next tier of frequently used experts in system RAM, and the rest on the NVMe SSD. A miss cascades SSD to RAM to VRAM, because the GPU needs those experts in VRAM to do the math.
  • Prefetch. The post says Magnitude predicts upcoming experts and reads them from disk before the GPU needs them. The README says those reads are strictly read-only, so streaming causes zero SSD wear, and that it uses direct uncached reads instead of OS disk swap.
  • What changes speed. The post says VRAM has to fit at least the active experts. More cache in VRAM and RAM is faster. For whatever still spills, a faster SSD, such as PCIe 5.0, matters.
  • Apple Silicon. The hardware docs say Apple Silicon shares memory between the CPU and GPU, and that macOS and other apps use that same pool, so a Mac with 32 GB does not have all 32 GB for a model. On the clinic's Mac mini the VRAM and RAM sliders are two budgets inside one pool, drawn apart so the cascade is visible. A discrete GPU really does have separate VRAM.
  • Claimed by the author. @tomgreenwald lists these speeds for 2-bit quants at 64k context, and calls them the worst these speeds will ever be. magnitude.dev shows the same four lines and labels them decode speed, 2-bit, 64k context, speculative decoding on. This page does not reproduce them.
    • Mac mini M5 Pro (48 GB): 54 tok/s, Qwen 3.8 Flash Next
    • RTX 3090 + 64 GB RAM + PCIe 4.0 SSD: 41 tok/s, Qwen 3.8 Flash Next
    • DGX Spark (128 GB): 28 tok/s, GLM 5.3 Flash
    • RTX 5090 + 128 GB RAM + PCIe 4.0 SSD: 17 tok/s, DeepSeek V4.1 Flash

The docs also say kernels are tuned on your chip and that the project is over 2x faster than Ollama on average across popular local models. Those are the project's claims. This sketch does not model kernel tuning, speculative decoding, or a comparison with another engine. Docs: introduction, hardware, FAQ. Benchmarks as published by the project: magnitude.dev/benchmarks.

The clinic's Mac mini, one toy layer

Dana Cho, a fictional clinician, drafts on the office Mac mini. The grid is one simplified layer of 256 experts. Each token routes 12 of them, 12 / 256, which is about 5%. Shared layers are assumed to sit in the hot tier already, so they are not drawn. Each toy expert is 8 MiB. That size is made up so the byte counts are easy to read.

Stand-in speeds, not measurements: RAM 50 GB/s. SATA 0.5 GB/s, PCIe 4 5 GB/s, PCIe 5 12 GB/s. If every routed expert is already in VRAM and the 12 fit, the sketch adds 12 ms of compute, about 83 tok/s. A correct prefetch can overlap that 12 ms. Bytes from a wrong guess are extra SSD time and are not hidden. That ceiling is a round number for this page. It is not the 54 tok/s claimed by the author.

Three ways the cache stops helping

1. Near-uniform routing

A visit note keeps reusing one band of experts, so the hot slots earn their keep. A prompt mix that hops topics, or a skew near zero, spreads the 12 picks across the catalog. The same VRAM and RAM then miss, and SSD bandwidth dominates the made-up tok/s.

2. VRAM below the active set

The quoted post says VRAM has to fit at least the active experts. At 8 slots the 12 experts this token routes cannot all stay resident. The sketch adds a stall in proportion to the shortfall, and modeled tok/s falls off a cliff even when RAM is large and the note repeats.

3. Prefetch that guesses wrong

Prefetch hides SSD time only when the guess is an expert the token actually uses. The misprediction slider marks the rest as wasted reads. At 100% wrong, those bytes still move, and the real experts are read as well.
