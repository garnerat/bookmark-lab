Naive scan vs a 6-phase audit

Hilltop Homebook is a made-up Cincinnati shop app for booking heating, plumbing, and electrical visits. Five short files are the whole codebase. A single-pass scan flags every one of them. A six-phase audit challenges each candidate, then files a report.

The phases are from Cloudflare Developers’ post about the open-source security-audit skill. The skill’s names for the same six phases are reconnaissance, coverage-led hunting, candidate validation, structured output, independent record verification, and target-neutral reporting.

Simulation. This is not a scanner. Hilltop Homebook, the five files, the scan, and every verdict are canned examples in this tab. The token in the third file is a placeholder written for the demo.     The six phases

    1. Map the codebase. Architecture, the trust boundary, and the input surfaces.
    2. Hunt for vulnerabilities. One hunter per file. Candidates only.
    3. Challenge each candidate. A fresh pass tries to disprove it.
    4. Record the findings. Confirmed, rejected, or needs validation.
    5. Verify the findings. Another pass checks each record against the source.
    6. Report what's confirmed, rejected, or still needs validation.

    What to steal for your own agent workflow

    1. Map the trust boundary before you pattern-match. Write down who can call each route, and which values are untrusted, before a rule flags a line.
    2. Give every candidate to a fresh pass whose job is to disprove it. The pass that found it does not grade it.
    3. Record three verdicts. Confirmed has a source trace and a result you can point at. Rejected keeps the disproof. Needs validation names the one open fact and has no severity.
    4. Derive the report from those records. The first list of hits is not the report. A rejected false positive stays on the record.
